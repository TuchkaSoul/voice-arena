# Voice Synth — сторона синтеза

Генерирует речь по корпусу фраз, прогоняет её через канал передачи
(кодек) и пишет манифест, который читает сторона анализа.

Предварительные измерения текущего анализатора — в [RESULTS.md](RESULTS.md).

```
текст → нормализация → движок → канал → файл + строка манифеста
```

---

## Устройство

| Модуль | За что отвечает |
| --- | --- |
| `synth/text.py` | нормализация русского: числа, проценты, сокращения |
| `synth/engines/` | движки синтеза за одним интерфейсом `SynthEngine` |
| `synth/channel.py` | кодеки через ffmpeg, всё приводится к 16 кГц моно |
| `synth/manifest.py` | JSONL-контракт со стороной анализа |
| `synth/pipeline.py` | порядок ступеней, и больше ничего |
| `presets/` | настройки движков — файлами, а не в коде |
| `corpus/` | общий набор фраз для всех раундов |

### Числа, время и даты

Нормализация теперь разворачивает десятичные дроби с запятой или точкой
(до девяти знаков), время `HH:MM` / `HH:MM:SS`, отрицательные числа
с `-` / `−` и число месяца с ближайшим предлогом.

| Исходный текст | На входе модели |
| --- | --- |
| `3,5 секунды` | три целых пять десятых секунды |
| `0,05%` | ноль целых пять сотых процента |
| `в 09:01` | в девять часов одну минуту |
| `с 09:05 до 18:30` | с девяти часов пяти минут до восемнадцати часов тридцати минут |
| `-10 °C` | минус десять градусов цельсия |
| `к 15 марта` | к пятнадцатому марта |
| `на 3 июня` | на третье июня |
| `с 1 по 3 мая` | с первого по третье мая |

Нули после разделителя сохраняют точность: `0,05` — пять сотых,
`0,005` — пять тысячных. У дробных величин единица читается в родительном
единственного числа. Тире и дефисы диапазонов не превращаются в минус.
Некорректное время (`24:00`, `12:60`) и невозможное число месяца
(`31 апреля`) вызывают понятную ошибку. Февраль допускает 29 дней:
год и високосность здесь не разбираются.

Это правила для конкретных форматов, не полный морфологический разбор.
Склонение обычных числительных по всему предложению, дроби `1/2`,
числовые даты `15.03.2026` и неоднозначные записи пока не поддерживаются.
Для времени учитываются ближайшие `в`, `во`, `на`, `с`, `со`, `до`,
`после`, `от`; остальные контексты требуют отдельной поддержки.

Для проверки добавлен отдельный корпус из 12 фраз, старые корпуса
не изменены. Из папки `synth/`:

```powershell
.venv-f5/Scripts/python.exe main.py synth --preset f5_ru --channel clean opus_24k --run r3-normalization-20261013 --corpus corpus/phrases_numeric_v1.txt --prefix N
```

Нормализованный текст записывается в манифест каждой записи.
Локальное сравнение текста до/после лежит в
`runs/r3-normalization-20261013/normalization.jsonl`.

Для отдельных проверенных слов F5 поддерживает словарь `text.stress_overrides`
в пресете. Добавлена подсказка `зиме: зим+е`: в первой фразе о мосте
было замечено неверное ударение. Словарь применяется при `strip_stress: false`,
сохраняет регистр и не меняет буквы слова. Другие формы («зима», «зимой»)
и явно размеченные в исходном тексте слова остаются как заданы.
Это ручные подсказки, не автоматическая расстановка ударений и не
правило для неоднозначных слов вроде «замок».

Первую фразу можно повторить с исправлением:

```powershell
.venv-f5/Scripts/python.exe main.py synth --preset f5_ru --channel clean opus_24k --run r4-stress-zime-20261013 --corpus corpus/phrases_long_v1.txt --prefix L --limit 1
```

Пять решений приняты осознанно, и ломать их не стоит.

**Движок — сменная деталь.** Всё, что не движок, знает только
`SynthEngine` из `engines/base.py`. Новый движок — новый файл плюс
строчка в `engines/registry.py`; пайплайн не трогается.

**Пресеты — файлы.** Правило из README проекта: детектор не должен
видеть все атаки заранее. Закрытые пресеты лежат в `presets/held_out/`,
папка целиком в `.gitignore`. Пока настройки были бы аргументами
командной строки, соблюсти это правило было бы нельзя — они утекли бы
в историю команд и в ревью.

**Канал отделён от синтеза.** `apply()` работает с файлом, а не с
движком, поэтому живые записи проходят ровно тот же код
(`main.py channel`). Иначе детектор научится отличать не человека от
машины, а wav от opus.

**Фраза синтезируется один раз на все каналы.** И VITS, и XTTS берут
шум случайно, поэтому повторный синтез той же фразы даёт другую запись.
Если бы каждый канал синтезировал заново, `p0001` в `clean` и `p0001` в
`opus_24k` были бы разными записями, и разница в метриках показывала бы
разброс синтеза, а не деградацию от кодека. Между каналами меняется
только канал. Инвариант закреплён тестом в `tests/test_pipeline.py` —
если кто-то перепишет пайплайн и сломает это, тест упадёт.

**Громкость выравнивается одинаково для обеих сторон.** Каждый канал
включает `loudnorm`. Без этого piper отдавал бы файлы с пиком ровно
1.000 (он так нормализует по умолчанию), XTTS — нет, а живая запись с
микрофона тем более, и детектор выучил бы уровень громкости вместо
артефактов синтеза. Это та же ловушка, что водяной знак в chatterbox,
только сделанная своими руками. Отключать `loudnorm` можно только
одновременно для синтеза и для живого корпуса.

## Движки

| Имя | Роль | Статус |
| --- | --- | --- |
| `piper` | слабая атака: ONNX, без torch, CPU | работает, ×1.0 realtime на CPU |
| `xtts` | сильная атака: клонирование по образцу | код готов, нужен `coqui-tts` и образец голоса |
| `f5` | F5-TTS_RUSSIAN, клонирование по образцу и его расшифровке | локальный запуск, пресет `f5_ru` |
| `chatterbox` | запасной вариант | заглушка, см. файл |

## Установка

Проверено на **Python 3.13** и **ffmpeg 9.0.1** (Windows 11).
Каркас собирается и на 3.11 — на нём работает сторона анализа, у неё
`onnxruntime==1.18.1` и `numpy==1.26.4`, которые под 3.13 не встанут.
Два приложения соединены файлами, поэтому окружения у них независимые.

### ffmpeg

```bash
winget install --id Gyan.FFmpeg -e
```

После установки **перезапустить терминал** и проверить:

```bash
ffmpeg -version
```

### Python-зависимости

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Если torch с CUDA уже стоит глобально, venv лучше создать с
`--system-site-packages` — иначе XTTS потянет ещё ~3 ГБ в копию:

```bash
python -m venv .venv --system-site-packages
```

### Голоса Piper

Качаются штатным загрузчиком, в репозиторий не кладутся:

```bash
python -m piper.download_voices ru_RU-irina-medium ru_RU-denis-medium --download-dir voices
```

Должно получиться по два файла на голос — `.onnx` и `.onnx.json`.
Если загрузка оборвалась и `.onnx.json` не появился, движок скажет об
этом прямо; добрать можно так:

```bash
curl -L -o voices/ru_RU-denis-medium.onnx.json https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/denis/medium/ru_RU-denis-medium.onnx.json
```

### XTTS (сильная атака)

```bash
pip install coqui-tts "transformers<5"
```

Именно `coqui-tts` — оригинальный пакет `TTS` заброшен после закрытия
Coqui. Веса (~1.8 ГБ) скачаются сами при первом запуске.

Ограничение `transformers<5` обязательно: coqui-tts импортирует
`isin_mps_friendly`, которую пятая ветка выкинула, и без пина установка
падает на импорте. Проверено на `transformers 4.57`.

**Если скачивание весов обрывается.** Загрузчик coqui не умеет
докачивать: при обрыве он удаляет всё скачанное и начинает сначала, так
что на нестабильной сети 1.86 ГБ можно не добрать никогда. Штатный
обходной путь — положить файлы руками, `TTS` увидит непустую папку и
качать не станет:

```bash
DIR="$HOME/AppData/Local/tts/tts_models--multilingual--multi-dataset--xtts_v2"
mkdir -p "$DIR"
for f in config.json vocab.json hash.md5 speakers_xtts.pth model.pth; do
  curl -L --retry 15 --retry-all-errors -C - -o "$DIR/$f" \
    "https://huggingface.co/coqui/XTTS-v2/resolve/main/$f"
done
```

Ключ `-C -` и есть всё отличие: curl продолжает с места обрыва.

**Про md5.** `hash.md5` в репозитории XTTS-v2 разошёлся с самим
`model.pth`: файл скачивается ровно того размера, что объявляет
Hugging Face (1 867 929 118 байт), но контрольная сумма не совпадает с
записанной в `.models.json`. Модель при этом грузится и синтезирует
нормально — проверено. Просто не пугайтесь несовпадения и не считайте
его признаком битой загрузки; сверяйте размер.

Опорные образцы голоса — `voices/speaker_ru_*.wav`, по 6–10 секунд
чистой речи каждый. XTTS принимает список, и на нескольких образцах из
разных мест записи тембр держится заметно стабильнее, чем на одном. **Это
должен быть голос кого-то из команды.** Голоса посторонних людей —
дикторов, актёров, публичных персон — не клонируем: это правило из
README проекта, и первый же коммит с чужим голосом его обнуляет.

### F5-TTS_RUSSIAN

Для сравнения используется базовый русский checkpoint `model_240000_inference.safetensors`
из [Misha24-10/F5-TTS_RUSSIAN](https://huggingface.co/Misha24-10/F5-TTS_RUSSIAN),
его **русский `vocab.txt`** и Vocos 24 кГц. Веса имеют лицензию CC BY-NC 4.0.
Версии файлов закреплены в `setup_f5.py` и пресете. Загрузчик продолжает
оборванные загрузки через curl, проверяет размер и SHA-256 больших файлов,
сохраняет происхождение и контрольные суммы в локальных `models/*/source.json`.

Ставить в отдельное окружение, чтобы зависимости F5 не затронули XTTS.
Проверено на Python 3.13 с уже установленными torch/torchaudio 2.7.0+cu128.
Если torch отсутствует, сначала установи совместимую пару для своей CUDA
по [инструкции F5](https://github.com/SWivid/F5-TTS#installation).

```powershell
python -m venv .venv-f5 --system-site-packages
.venv-f5/Scripts/python.exe -m pip install -r requirements-f5.txt
.venv-f5/Scripts/python.exe -m pip install --no-deps f5-tts==1.1.22
.venv-f5/Scripts/python.exe setup_f5.py
```

`--no-deps` исключает ненужные для этого API интерфейс Gradio, bitsandbytes
и torchcodec. Нужные при импорте зависимости Trainer перечислены в
`requirements-f5.txt`, хотя обучение здесь не запускается.

Образец — собственная запись команды `voices/speaker_ru_1.wav`, 8 секунд,
из того же исходника, который использовали для XTTS. F5 также требует
соответствующий текст в `voices/speaker_ru_1.txt`. Его можно записать вручную
либо однократно распознать локальным Whisper Base:

```powershell
.venv-f5/Scripts/python.exe setup_f5.py --transcribe-reference
```

ASR-расшифровку нужно проверить на слух. Пустой текст не допускается:
движок не запускает скрытую загрузку Whisper Large. В пресете `strip_stress: false`
сохраняет `+` перед ударной гласной; первый прогон использует исходный корпус
без дополнительной разметки ударений. Неизвестные русскому словарю символы
вызывают ошибку до синтеза, чтобы модель не пропускала их незаметно.

```powershell
.venv-f5/Scripts/python.exe main.py synth --preset f5_ru --channel clean opus_24k --run r2-f5 --corpus corpus/phrases_long_v1.txt --prefix L
.venv-f5/Scripts/python.exe main.py channel --src voices/Запись.m4a --channel clean opus_24k --run r2-f5 --name live_control
```

Для независимого контроля используй новую запись в команде `channel`
с другим `--name`. Исходник образца служит только предварительным контролем.
Синтез каждой фразы выполняется один раз для двух каналов, loudnorm и
кодеки совпадают с обработкой живых записей.

Из папки `analyzer/` оценить синтез и контроль одним запуском:

```powershell
../synth/.venv/Scripts/python.exe main.py --manifest ../synth/runs/r2-f5/f5_ru.phrases_long_v1.clean.jsonl ../synth/runs/r2-f5/f5_ru.phrases_long_v1.opus_24k.jsonl ../synth/runs/r2-f5/live_control.clean.jsonl ../synth/runs/r2-f5/live_control.opus_24k.jsonl --manifest-root ../synth --jsonl ../synth/runs/r2-f5/analysis.f5.jsonl
```

Из `synth/` получить доли ошибок отдельно по классам и каналам:

```powershell
.venv/Scripts/python.exe main.py evaluate --manifest runs/r2-f5/f5_ru.phrases_long_v1.clean.jsonl runs/r2-f5/f5_ru.phrases_long_v1.opus_24k.jsonl runs/r2-f5/live_control.clean.jsonl runs/r2-f5/live_control.opus_24k.jsonl --results runs/r2-f5/analysis.f5.jsonl
```

### Второй голос — matv

Для предоставленного голоса matv добавлен отдельный пресет `f5_matv`.
Исходники — `voices/matv.wav`, `voices/matv.m4a`, расшифровка —
`voices/matv.txt`. Запись WAV длится 18.08 с, поэтому для F5 подготовлен
фрагмент 5.15–11.80 с: `voices/matv_ref.wav` и соответствующий текст
`voices/matv_ref.txt`. Границы выбраны внутри пауз. Текст фрагмента
взят из предоставленной расшифровки, полный текст к короткому аудио
не подставляется. Исходники остаются локально в `voices/`.

Модель и настройки генерации те же, что у `f5_ru`; меняются образец и
текст образца. Прежний голос выбирается через `f5_ru`, новый — через
`f5_matv`. Подсказка `зим+е` действует в обоих пресетах.

```powershell
.venv-f5/Scripts/python.exe main.py synth --preset f5_matv --channel clean opus_24k --run r5-matv-20261013 --corpus corpus/phrases_v1.txt --prefix p --limit 3
.venv-f5/Scripts/python.exe main.py synth --preset f5_matv --channel clean opus_24k --run r5-matv-20261013 --corpus corpus/phrases_long_v1.txt --prefix L --limit 1
```

Пути и контрольные суммы образца сохранены локально в
`runs/r5-matv-20261013/reference.json`. Сходство тембра и естественность
оцениваются при прослушивании.

## Запуск

```bash
python main.py presets                                  # что есть
python main.py channels                                 # какие каналы
python main.py normalize "Скидка 25% до 15 марта"       # проверка текста, без моделей
python main.py synth --preset piper_irina --channel clean --run r0 --limit 3
python main.py synth --preset piper_irina --channel opus_24k mp3_64 --run r0
python main.py synth --preset piper_irina --channel all --run r0     # все каналы сразу
python main.py synth --preset piper_irina --channel all --run r0 \
    --corpus corpus/phrases_long_v1.txt --prefix L                   # длинный корпус
python main.py channel --src live_raw --channel opus_24k --run r0    # живой корпус
python main.py channel --src voices/Запись.m4a --channel all --run r1-control --name live_control
```

`--channel` принимает несколько имён или `all`. Синтез при этом идёт
один раз, а каналы расходятся веером — так и быстрее, и корректнее
(см. выше про инвариант).

### Контроль живого голоса и оценка анализатора

Команда `channel` принимает папку или один файл, в том числе `.m4a`.
Для живой записи она ставит метку `bonafide` и применяет те же каналы,
что и к синтезу. Запись `voices/Запись.m4a` уже служила образцом для
XTTS, поэтому она годится только для предварительной проверки. Для
измерения ложных тревог нужна новая запись, не использованная при
создании голоса, желательно несколько разных дикторов и фраз.

Анализатор может прочитать выбранные манифесты за один запуск и
сохранить оценки в JSONL. Из папки `analyzer/`:

```bash
python main.py --manifest ../synth/runs/r0/xtts_ru.phrases_long_v1.clean.jsonl ../synth/runs/r1-control/live_control.clean.jsonl --manifest-root ../synth --jsonl ../synth/runs/r1-control/analysis.clean.jsonl
```

Затем из папки `synth/`:

```bash
python main.py evaluate --manifest runs/r0/xtts_ru.phrases_long_v1.clean.jsonl runs/r1-control/live_control.clean.jsonl --results runs/r1-control/analysis.clean.jsonl
```

Отчёт отдельно показывает долю синтеза, принятого за живой голос, и
долю живых записей, названных синтезом. Файлы без оценки учитываются
отдельно, чтобы ошибки обработки не улучшали метрику.

Когда сравниваем несколько моделей, голосов или раундов, добавляем
`--by-dataset`. Иначе сводка объединяет их по каналу и классу:

```bash
python main.py evaluate --manifest runs/r9-detector-audit-20261013/input.jsonl --results runs/r9-detector-audit-20261013/analysis.jsonl --by-dataset
```

В этом режиме каждая строка относится к отдельному раунду, пресету,
корпусу и каналу. Дополнительно видны число оценок нейросети выше порога
и число смен класса между нейросетью и итоговым вердиктом. Пропуски и
ложные тревоги считаются по итоговому вердикту, как и раньше. Если
анализатор запускали с другим `--threshold`, такой же порог нужно
передать через `--model-threshold`. Старые JSONL без `model_score`
сохраняют итоговые метрики, но не участвуют в сравнении с нейросетью.

В таблице анализатора процент рассчитывается из итогового балла.
Например, «ЖИВОЙ 60%» может получиться из ограничения балла правилом
до 0.4. Это не измеренная вероятность того, что говорит человек.
Для разбора нужны полный JSONL, исходные пути и контрольные суммы:
одно имя `L0001.wav` встречается у нескольких моделей и раундов.

### Корпуса

| файл | фраз | длина | префикс |
| --- | --- | --- | --- |
| `corpus/phrases_v1.txt` | 20 | 0.7–6 с | `p` |
| `corpus/phrases_long_v1.txt` | 10 | 22–28 с | `L` |
| `corpus/phrases_numeric_v1.txt` | 12 | числа, время и даты; длительность зависит от модели | `N` |

Короткий корпус проверяет крайние случаи: числа, сокращения, реплики
в одно слово. Длинный даёт больше речи для анализа. Текущий анализатор
использует Wav2Vec2: после VAD берёт первые 15 секунд выделенной речи,
делит их на окна по 5 секунд и усредняет оценки. Короткое последнее
окно дополняет тишиной до одной секунды. Поэтому общая длина файла
не равна объёму речи, реально рассмотренному нейросетью.

**У каждого корпуса свой `--prefix`.** Иначе `p0001` из одного набора
столкнётся с `p0001` из другого. Имя корпуса входит и в путь, и в имя
манифеста, так что два набора в одном раунде не перезапишут друг друга.

Результат:

```
runs/r0/piper_irina/phrases_v1/opus_24k/p0001.ogg        ...
runs/r0/piper_irina.phrases_v1.opus_24k.jsonl            ← это читает сторона анализа
runs/r0/piper_irina/phrases_long_v1/opus_24k/L0001.ogg   ...
runs/r0/piper_irina.phrases_long_v1.opus_24k.jsonl
```

Тесты (моделей не требуют, ffmpeg-тесты пропускаются без него):

```bash
pytest
```

## Манифест

Одна строка JSON на запись. Команда `evaluate` соединяет манифест с
результатами анализатора по полному пути файла. Одинаковые `utt_id`
в разных пресетах не объединяются.

```json
{"schema":"voice-arena/manifest@2","utt_id":"p0003",
 "text":"Встреча перенесена на 15 марта, начало в 14 часов 30 минут.",
 "text_normalized":"Встреча перенесена на пятнадцать марта, начало в четырнадцать часов тридцать минут.",
 "label":"spoof","engine":"piper","preset":"piper_irina","channel":"opus_24k",
 "path":"runs/r0/piper_irina/phrases_v1/opus_24k/p0003.ogg","sr":16000,"engine_sr":22050,
 "duration_sec":5.074,"sha256":"...","run_id":"r0","seed":1337,"created_at":"...",
 "corpus":"phrases_v1"}
```

Схема `@2` добавила поле `corpus` — без него по манифесту нельзя
сказать, из какого набора фраз запись, а наборов теперь два. Поле
необязательное, читатель `@1` его просто не заметит.

`text_normalized` — то, что движок реально произносил. WER считать надо
относительно него, а не относительно `text`: иначе мы штрафуем
распознавание за то, чего синтезатор не говорил.

`label` — `spoof` для синтеза, `bonafide` для живых записей.

## Чего пока нет

- **Канал `room`** (колонка + микрофон) — раунд 5, физическая запись,
  из ffmpeg не получается. Имя зарезервировано, `channel.get("room")`
  честно падает с объяснением.
- **Конверсия голоса** (FreeVC / kNN-VC) — отдельный класс атак,
  встанет ещё одним движком.
- **Полная воспроизводимость по сиду.** Для F5 `--seed` теперь явно
  передаётся в каждый вызов модели и записывается с фактическими параметрами.
  Seed в `generate_params` пресета имеет приоритет. Один seed используется
  для каждой фразы, поэтому изменение порядка корпуса не меняет этот вход.
  Полная побитовая повторяемость GPU не гарантирована. У VITS и XTTS
  остаются внутренние источники случайности, не управляемые `random.seed`.
- **Общее склонение числительных** в нормализации. Даты с предлогами,
  основные контексты времени и десятичные дроби уже разворачиваются.
  Обычные числа в контексте «с 1200 до 870» пока остаются в именительном
  падеже. Дроби вида `1/2`, цифровые даты с годом и римские цифры
  требуют отдельных правил.

## Сравнение шума, настроек F5 и ранних отражений

Из каталога `synth/`, в окружении `.venv-f5`, с уже загруженными локальными
весами и ffmpeg:

```powershell
.\.venv-f5\Scripts\python.exe compare_f5.py --voices f5_ru f5_matv --seeds 1337 --reserve-sec 0.65 --out runs/my-quality-check
```

Нужен новый выходной каталог: старые эксперименты не перезаписываются.
Скрипт использует ту же модель и те же образцы, что пресеты. Для двух
коротких текстов сравнивает 32 шага/CFG=2, 48 шагов/CFG=2,
48 шагов/CFG=1.5. У всех одинаковые seed, скорость и запас времени.
`fix_duration` включает образец и будущую речь, как в API F5.
Запас — дополнительные кадры генерации, а не вставленная тишина.

Для последней настройки отдельно получаются мягкое ослабление ВЧ
(`treble`, −2.5 дБ, частота перехода 5 кГц) и модель ранних отражений
(11–73 мс, суммарная амплитуда отражений 8% от прямого звука).
Они используют один исходный WAV, повторной генерации и добавленного
случайного шума нет. Это модель акустики, отдельная от физического `room`.

Внутри результата: `listen.html` с плеерами, сырые WAV float32 без
обрезки пиков, WAV 24 кГц для прослушивания, штатные WAV 16 кГц и Opus,
манифест и `comparison.jsonl`. У файлов для прослушивания общая цель
громкости −23 LUFS. Точные параметры, версии, хэши моделей и исходников
и копии скриптов сохраняются рядом. `--reserve-sec 0` повторяет штатную
оценку длины, но у коротких фраз возможны звучащие окончания на границе.
Для независимого повтора используйте другой каталог и, например,
`--seeds 1337 2026`.

Проверка неизменённым анализатором из каталога `analyzer/`:

```powershell
..\synth\.venv\Scripts\python.exe main.py --manifest ../synth/runs/my-quality-check/manifest.jsonl --manifest-root ../synth --jsonl ../synth/runs/my-quality-check/analysis.jsonl
```

Сначала задайте `USE_TF=0`, `USE_TORCH=1`, `HF_HUB_OFFLINE=1`, если
используете локальное окружение из прошлых прогонов. Файлы доступны
офлайн. Для просмотра страницы можно открыть `listen.html` в браузере
или запустить локальный сервер только для каталога эксперимента:

```powershell
.\.venv-f5\Scripts\python.exe -m http.server 8767 --bind 127.0.0.1 --directory runs/my-quality-check
```

Открыть `http://127.0.0.1:8767/listen.html`. Сервер и незавершённый
прогон останавливаются Ctrl+C в их терминале. Модель обучаться не начинает,
веса не изменяются. Для чистого повторения создайте окружение по инструкции
F5 выше, загрузите закреплённые веса, задайте те же образцы и запустите в
новый каталог. Сбрасывать или удалять историю для повтора не требуется.

Балл детектора, энергия ВЧ и шум на слух — разные свойства. Ослабление
ВЧ затрагивает также согласные, отражения меняют окраску; ни одна обработка
не объявляется улучшением до прослушивания. Настройки базовых пресетов
этим экспериментом не заменяются. История проверок — в [log.md](log.md).

Технические источники:
[API и ограничения генерации F5](https://github.com/SWivid/F5-TTS/tree/main/src/f5_tts/infer),
[описание русской модели](https://huggingface.co/Misha24-10/F5-TTS_RUSSIAN).
В эксперименте используется закреплённая в пресетах ревизия, а не
автоматическая замена модели последней опубликованной версией.

### Проверка ресемплера и входной частоты Opus

Опыт 18 октября 2026 показал зависимость итогового каскада от подготовки
